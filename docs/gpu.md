# GPU acceleration

Pages paint with Skia on the CPU by default. Optional GPU paths take over
presentation:

| Path | Enable with | Provides |
| --- | --- | --- |
| QEMU virtio-gpu | `make run RUN_ARGS='--graphics virtio-gpu'` | 2D display transport |
| QEMU virgl | `make run RUN_ARGS='--graphics virgl'` (needs a host GL display) | Cached page textures, GPU scrolling, [GPU rasterization](#gpu-rasterization) and [compositing](#gpu-compositing) in pages |
| Redmi 2 Adreno 306 (experimental) | `make phone REDMI2_ADRENO_FIRMWARE=build/redmi2-adreno` | GPU scrolling and scaling to 720×1280 |

Layout and JavaScript stay on the CPU, and there is no WebGL. If a GPU is
missing or fails, SOS2 keeps using the CPU. Only the kernel owns GPU devices,
queues and buffers: pages never see MMIO or GPU addresses, and page memory is
never mapped for DMA.

## QEMU

RAMFB is the default display. With `--graphics`, QEMU gets a GPU console and
a second, RAMFB console that takes over if the GPU fails. The driver
(`kernel/virtio_gpu.c`, QEMU only) follows
[virtio 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)
and the [virgl protocol](https://gitlab.freedesktop.org/virgl/virglrenderer/-/blob/main/src/virgl_protocol.h).
Only the boot CPU submits, one command at a time; any failure resets the
GPU. With virgl the kernel composes frames from cached page textures and
moves scrolls on the GPU.

`SYS_GPU` (`kernel/protection/gpu_client.c`) gives each page its own virgl
context. The kernel picks the ids and attaches each resource only to the
creating page's context, so a command stream cannot reach another page's
resources; budgets cap resources per page and in all.

## Mesa in pages

`tools/build_native_mesa.py` builds Mesa 26.2.0 (pinned in
`tools/browser/native-mesa.lock.json`, patched by
`tools/browser/patches/mesa-26.2.0-sos2.patch`) as static archives:
surfaceless EGL, OpenGL ES 2 and the virgl driver. Programs link it with the
libdrm shim in `sdk/drm`, which serves `/dev/dri/renderD128` from user space
on top of `SYS_GPU`. There are no cube maps, array textures or multisampling.

## GPU rasterization

With virgl, pages paint web content with Skia's GL backend on Mesa
(`programs/browser/web_gpu.h`) into a GPU surface they present with
`USER_GPU_PRESENT`; scrolling copies pixels on the GPU. A probe pixel read
back every 250 ms detects a silently failed context; a lost GPU sends the
page back to the CPU for good. `gpuRasterization` in
`programs/browser/web_main.cpp` turns it off.

## GPU compositing

When a page paints on the GPU, WebKit's TextureMapper
(`programs/browser/web_gpu_compositor.h`) composites its layers with GL into
the page's GPU surface: it runs transform, opacity and filter animations
itself and draws masks, filters and 3D transforms, which the CPU compositor
flattens. When a page uses a non-normal CSS `mix-blend-mode`, WebCore paints
directly into the GPU surface and animates on the page thread. Layer compositing
resumes when those blend modes are removed. SOS2 commits and draws the layer
tree on the page thread after WebCore's layer flush
(`tools/browser/patches/wpe-2.52.6-native-gpu-compositing.patch`).
`gpuCompositing` in `programs/browser/web_main.cpp` turns it off.

## Redmi 2 Adreno

An experimental A306 driver (`boards/redmi2/adreno.c`) runs fixed compute
programs (`boards/redmi2/adreno_shaders.h`, generated by
`tools/adreno_shader.py`) that move retained scroll pixels and scale the
480×800 composition to the 720×1280 panel. Other display formats, missing
firmware or a failed startup keep CPU presentation.

- **Firmware:** Linux's A300 PM4/PFP pair from linux-firmware
  `69e51bb26f3fa3e118dd770f1962a93bed690dc1`. `make fetch` downloads it into
  `build/redmi2-adreno` and `tools/adreno_firmware.py` checks it; packaging
  adds it under `/firmware/adreno/`.
- **Isolation:** the GPU sees only the driver's own 9 MiB arena through its
  SMMU contexts, never the scanout, page tables or process memory.
- **Safety:** acceleration starts only after a boot-time self test checks
  every output pixel. One job runs at a time, and pixels reach the scanout
  only after its fence; a fault or a 100 ms timeout resets the core and
  returns to CPU composition.
- **Power:** in standby an idle GPU's power domain goes off, as KGSL's
  slumber, and waking restarts its engine.

Firmware execution, timing and power use are not yet qualified on the
handset. Licenses: `boards/redmi2/adreno-notices.txt` and
`third_party/adreno/LICENSE.GPL-2`.
